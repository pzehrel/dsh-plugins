# 完整浏览器能力通过插件与宿主公开接口协作实现

状态：历史决策，已被用户后续明确的“只能做插件，不能修改主程序”约束推翻；原接口设计与实现未开始。

当前仅研究和验证现有公开插件契约下的复用路线，不以宿主扩展或未来宿主版本作为交付前提。原生共享页面要求仍保留；无法满足的完整能力须明确报告并由用户决定范围，不能自动视为获准删除。参见[纯插件复用研究](../../../../../plugins/agent-browser/docs/plugin-only-reuse-research.md)。以下保留原决策及其历史理由，不再作为当前实施指引。

用户要求原生侧栏页面及完整自动化、文件与调试能力，而当前 DSH Desktop 存在下载拒绝、调试接口缺失等宿主限制。决定保留完整需求：插件负责自身功能，超出现有公开契约的能力在 DSH 上游补正式接口，不以修改安装包、调用私有 IPC、外部浏览器或画面流替代来绕过。

这接受了对宿主新版本的依赖及两个项目的交付成本，换取原生共享页面体验和可维护的权限边界。实施顺序已确认：先验证“原生侧栏页面＋Agent 感知操作”的真实闭环，并形成宿主接口提案；宿主补齐后再完成文件、完整调试和持久化验收。前一阶段只是中间里程碑，未补齐并验证的功能不得标为完整交付。具体协议和支持版本必须依据实际工程验证确定，不能提前编造；此决策不授权立即修改宿主或提交远端事项。

参见[需求记录](../../../../../plugins/agent-browser/README.md)及[宿主能力证据](../../../../../plugins/agent-browser/docs/research.md#当前官方宿主证据)。

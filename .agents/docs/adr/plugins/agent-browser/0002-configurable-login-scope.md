# 登录态默认全局共享，并可改为工作区共享

状态：已接受（本轮需求访谈 Q7，Q11–Q13 补充）；实现尚未开始。

首版修订：用户已接受跨重启登录态延期，重开 DSH 后按需重新登录；标签页网址恢复仍是首版目标。下文“重启保留登录态”保留为后续目标，不再是首版交付条件。范围统一见[已确认首版范围](../../../../../plugins/agent-browser/docs/design.md#已确认首版范围)。

为减少日常网页任务中的重复登录，登录态提供“全局共享”和“工作区共享”两种配置，默认全局共享，而不是建议中的默认工作区隔离。全局共享意味着不同工作区可能使用同一网站账号；每个 DSH 会话仍拥有自己的标签页，Agent 默认不能操作其他会话的页面。登录态共享不自动授予跨会话页面操作权限，也不隔离同一网站账号的服务端状态。

应用重启后保留登录态和标签页网址，不承诺恢复未提交表单，不自动重放操作。全局与各工作区使用独立账号容器；切换范围不自动复制 Cookie、不删除旧容器，也不改变已有页面使用的账号容器。这样避免配置切换时无意扩散账号数据或在任务中途换号，代价是在另一范围中首次使用网站时可能需要重新登录。

这是已确认的完整目标规则；当前公开契约明确 process-local partition 的 Cookie/Web storage 不跨应用重启保留。首版接受该限制，不再沿用已失效的 [ADR 0003](0003-upstream-browser-capabilities.md)宿主扩展路线；网址恢复与登录态持久化须分别验收。

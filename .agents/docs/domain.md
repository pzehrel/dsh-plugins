# 领域文档

本仓库采用多上下文布局，按插件划分领域；
共享包仅在形成独立领域时单列上下文。
本文中的路径均相对于仓库根目录，ADR 集中存放在根目录 `.agents/docs/adr/` 下。

## 布局

- `GLOSSARY-MAP.md`：领域索引，指向各上下文的词汇表。
- `.agents/docs/adr/`：跨领域架构决策，直接存放在此目录，不放入领域子目录。
- `plugins/<插件>/GLOSSARY.md`：插件领域词汇表。
- `.agents/docs/adr/plugins/<插件>/`：插件内部架构决策。
- `packages/<包>/GLOSSARY.md`：独立共享领域词汇表。
- `.agents/docs/adr/packages/<包>/`：该共享领域的架构决策。

包边界不自动等于领域边界；纯工具包无需独立词汇表。

## 探索前读取

先读取根目录 `GLOSSARY-MAP.md`，再读取与当前任务相关的词汇表、
跨领域 ADR 及对应上下文 ADR。跨领域任务覆盖所有相关上下文。
读取跨领域 ADR 时，只检查 `.agents/docs/adr/` 的直接文件，不递归加载无关上下文的 ADR。
如果已有根目录 `GLOSSARY.md`，也读取其中的通用术语。

上述文件或目录不存在时，静默继续，不主动报告缺失或建议提前创建。
`domain-modeling` 在实际明确术语或决策时按需创建文档；
本次设置不生成空词汇表、领域索引或 ADR。

## 使用统一术语

事项标题、重构建议、诊断假设和测试名称使用相关词汇表中的术语，
避免词汇表明确排除的同义词。
概念尚未收录时，先判断是否误造术语；
确有缺口时留待领域建模处理，不把未经确认的叫法写成既定定义。

## 显式指出决策冲突

建议与现有 ADR 冲突时，指出 ADR 编号、冲突内容及重新讨论的理由，
不要静默覆盖已有决策。

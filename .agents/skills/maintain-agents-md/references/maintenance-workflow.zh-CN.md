# AGENTS.md 维护流程

新建说明层级、审查或压缩多个文件、解决指南冲突，或为其他 Agent 工具增加兼容性时，阅读本参考。
小型且无歧义的规则更新只需使用 Skill 正文。

## 1. 盘点实际生效的说明表面

先执行只读盘点：

- 根、嵌套、本地化和 Override 形式的 `AGENTS.md`；
- `.agents/rules/` 或仓库已有等价位置中的路由策略，包括暴露每个文件的上下文指针原文及任务分支；
- 会改变说明发现方式或大小限制的仓库配置；
- 只有仓库实际使用或用户要求的工具，才检查其专属说明文件。

只有诊断相关冲突确实需要且权限允许时，才检查用户级或全局说明。不得为了建立清单而扫描环境
文件、凭证、缓存、个人主目录中的任意内容或无关源码树。

针对有代表性的受影响路径确认实际生效的说明链。同目录 Override 行为、Fallback 文件名、Import
语法、路径作用域和受支持的兼容文件会因工具而异，也可能随时间变化。创建或重写兼容文件前，根据
当前官方文档验证行为。不要在多个工具中重复相同的始终加载规则。

自动发现结果只是一份索引。持久化其中的结论前，打开并验证权威来源。

## 2. 建立证据和置信度

使用能够确立规则的最小扫描范围，并按以下顺序优先取证：

1. 用户的直接要求和实际生效的仓库说明链；
2. 可执行脚本、CI 工作流、配置、Schema 和生成文件声明；
3. 持续维护的仓库文档；
4. 有代表性的源代码和测试；
5. 把 Git 历史作为导航信号，再通过当前事实来源确认。

对于命令，找到定义它的脚本、Manifest、任务运行器、CI Job、容器配置或 Wrapper。保留要求的工作
目录、服务名、执行顺序和环境包装器。仓库已经定义自己的命令时，不得根据框架默认值推断。

使用以下内部置信度标签：

- `verified`：当前权威来源直接支持；
- `probable`：多个间接信号支持，但没有权威来源；
- `unknown`：缺少证据或证据冲突。

只持久化已验证内容。限定描述或省略可能内容。只有选择会造成实质影响时，才询问未知内容。不得把
置信度标签写入仓库规则本身。

## 3. 按语义整理规则

建立可执行规则清单。为每项规则记录实际作用域、支持或否定它的证据、权威位置，以及以下一项操作：

- `keep`：当前、具体、有用且有证据支持；
- `update`：仍然有用，但被更强当前证据否定；
- `move`：仍然有用，但应由更窄的说明、`.agents/rules/`、`docs/`、Skill 或可强制执行机制负责；
- `remove`：通用、重复、过时、无法验证、临时、敏感或已由自动化完全执行；
- `confirm`：本地证据无法解决的真实策略或所有权冲突。

措辞不同但操作效果相同的规则属于重复，只保留最清晰、最具体的版本。权威明确时根据证据解决
冲突；只对 `confirm` 项询问用户，并说明各来源路径以及两种选择的实际影响。

不得把新模板追加在现有指南之后，不得在 Legacy 章节保留过时内容，也不得把冲突双方都留下等待
以后清理。保留无关的用户自有内容。Git 已跟踪文件时，依赖工作树 diff 恢复，不创建备份文件或
Commit。

## 4. 选择布局

- 根 `AGENTS.md` 保留广泛适用的工作规则和任务路由；
- 只有子树确实存在差异时才添加嵌套 `AGENTS.md`，而且只记录相对父级的差异；
- 仓库专属的详细工作策略放进 `.agents/rules/<topic>.md`，并按条件路由。说明每个目标管辖什么，
  并列出必须读取它的每个不同任务分支；不要用指针文字重复同一分支的同义表述；
- 产品、领域、架构、需求、Schema 和路线图放进 `docs/`；
- 可移植能力、脚本、模板和可复用工作流程放进 Skill；
- 只有用户要求，或实际使用的工具确实需要时才创建工具专属兼容文件。共享规则只保留一个权威
  位置。

不要默认给每个 Monorepo Package 或常见目录生成说明文件。嵌套文件必须由不同命令、工具、安全
边界或约定证明其必要性，而不是由目录本身的存在证明。

在选定的每个文件中，把规则的定义、触发条件、要求动作、例外和完成标准放在一起。如果一个聚焦
章节可以承载完整含义，就不要把同一项义务分散到概述、操作流程和最终检查中。

## 5. 在不削弱规则的前提下压缩

实际测量，不要估算。仓库没有规定预算时，使用以下软审查阈值，而不是把它们当作通用有效性限制：

- 根 `AGENTS.md`：达到 200 行或 16 KiB 时审查；
- 嵌套 `AGENTS.md`：达到 80 行时审查。

按以下顺序压缩：

1. 删除角色 Persona、引言、结论、通用建议、空章节，以及不会改变仓库专属决策或验证方式的
   空操作指令；
2. 删除重复规则，以及不再要求 Agent 执行任何动作的完全自动化规则；
3. 把项目文档摘要和可从环境低成本查询的事实替换为带条件的链接或权威来源，只保留非显然约定、
   原因和要求动作；
4. 把详细工作流程移到 `.agents/rules/`；
5. 把只适用于子树的差异移到最近的嵌套说明文件；
6. 合并相关条目，但不丢失触发条件、操作、例外或验证标准。

不得通过调高 Harness 上下文限制来代替精简说明层。

## 6. 验证最终产物

检查最终实际生效的说明链，而不只是编辑过程：

- 每个路径都存在，每个命令都与当前定义它的事实来源一致；
- 不存在未解决的占位符、模板括号、生成标记注释或空 Boilerplate；
- 长期指南中没有密钥、凭证、私有提示词、对话文本、用户请求原文、个人主目录路径、任务状态、
  路线图或工具清单；
- 根、嵌套、`.agents/rules/`、`docs/`、Skill 和兼容文件之间不存在重复权威来源；
- 每个上下文指针都说明目标管辖什么，覆盖要求读取它的不同任务分支，并且不会变成兜底路由；
- 每项规则的触发条件、动作、实质性例外和完成标准都放在一起；
- 嵌套说明只包含范围内的差异，而且不会默默弱化父级规则；
- 语言和本地化遵循仓库证据，要求的语言对应文件仍保持一致；
- 每个所选工具的兼容行为都是当前有效的；
- 最终 diff 会删除过时指南，而不是只增加更多内容；
- 仓库提供的文档、格式、链接和说明校验均已通过。

使用简短数量或列表汇报保留、更新、移动、删除和尚未解决的规则。说明未验证命令、无法运行的
检查、兼容性假设以及任何超过软预算的文件。

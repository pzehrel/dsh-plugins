# 代码注释和 docstring

涉及源代码注释、模块/文件头部、docstring、JSDoc/TSDoc，以及按注释语法划分的函数或字段注释时阅读本文件。代码注释的语言设置与 Markdown/API 文档设置相互独立，均由生效的
`AGENTS.md` 控制：明确启用时使用英语加且仅加一种本地化语言；未说明时只使用一种语言。当任务修改源代码时阅读本文件：在 `SKILL.md` 之后、编辑代码之前阅读，再根据当前源代码的注释语法阅读对应的一个示例文件。

## 最小交付

本 skill 下的代码改动，只有在下列每一项都有注释、或都写明了跳过理由时，才算完成：

- 你新增或修改的、消费者可达的每个可调用对象：参数、返回值与失败行为
- 你新增或修改的消费者可见集合中的每个成员：类型/类的字段、枚举成员、映射键、解构参数、schema 列、配置键、错误码
- 每个“从代码看不出原因”的实现代码块：重试与退避边界、清理顺序、不变量、错误转换、不显然常量、兼容性垫片、安全或性能约束
- 创建文件或实质性改变其职责时的文件头部

只复述声明的注释不满足要求，见「注释布局」。

## 注释布局

- 每条说明性注释或 docstring 都在同一位置使用一段选定语言的完整内容。
- 形式取决于读者。消费者会从编辑器悬停或生成的文档里读到什么，就用文档注释形式——TypeScript/JavaScript/Java 用 `/** ... */`，Rust 用 `///`，Python 用 attribute docstring。函数或方法体内的实现说明用普通行注释——TypeScript/JavaScript/Java/Rust 用 `//`，Python 用 `#`。把文档注释放进函数体不记录任何内容：对语句使用 `///` 时 rustc 会报 `unused doc comment` 并建议改用 `//`。
- 启用双语时，先写完整英语块（包括摘要和全部结构化签名标签），空一行后在同一注释/docstring 中写完整本地化块。不要交错语言，也不要拆到相邻注释中。不要为了翻译重复结构化标签；工具无法为同一标签承载两份描述时，在英语标签之后使用完整的本地化 prose/列表块。
- 不要写只复述声明的注释——名称、类型或参数列表。`/** Sets the timeout. */ setTimeout(ms: number)` 没有提供读者从签名看不到的信息，审查者也从中得不到任何东西。请改写为签名无法表达的内容（单位、默认值、取值范围、失败行为、顺序），否则删除。
- 注释要紧贴它说明的声明或最小实现代码块。优先保留一份权威注释；解释较长时链接到更详细文档。
- 仅在双语模式下把翻译当作保真度检查，比较声明、语气、条件、示例、术语和标识符。

## 文件级头部

创建或实质性修改源代码、可执行脚本、配置或 schema 文件时，在文件顶部添加一段选定语言的简洁头部；头部位于导入或声明之前、必需的 shebang、编码标记或许可证行之后。
启用双语时，两种语言块保留在同一头部中。说明文件职责、范围边界，以及不显然时的主要输入、输出、集成关系、副作用或不变量。头部应稳定且持久；它不是变更日志、符号索引或重复的
API reference。跳过生成/vendor 文件，以及仓库禁止头部的文件。

## 可调用签名覆盖

对每个消费者可见的函数、方法、构造器、回调、命令处理器或其他可调用对象，都要在声明处记录每个参数和返回值。摘要、参数名或类型标注本身不够。适用时说明参数的角色、接受的形状或约束、
可选性/可空性、默认值、单位、所有权/可变性，以及取消/时序行为。说明返回值的含义和形状、身份/所有权、同步/异步行为、副作用、顺序，以及失败或拒绝输入的行为。覆盖重载差异、泛型关系和不显然的
私有可调用对象。

支持结构化标签时，每个参数、返回值和抛出错误各使用一个唯一条目。描述使用选定语言。启用双语时，先放置包含全部标签的完整英语签名段，再放置完整本地化签名段；保持每个参数、返回值和错误都有覆盖，不要交错语言或重复标签。不支持标签的语言使用已有 docstring 的
`Args`/`Returns`/`Raises` 章节或最接近的等价形式。

每条注释都应紧贴它说明的声明或使用位置。JSDoc 的 `@typedef` 块是有意的例外，因为该块本身声明了可复用类型；只有类型确实会被引用时才使用它。对象只被一个可调用对象使用时，优先使用嵌套的参数属性标签，让每个字段明显附着在函数签名上。

## 成员集合覆盖

有些声明本身就是容器：消费者是通过其中的具名成员进入，而不是通过容器本身。把每个成员都视为独立文档目标，并在它自己的声明处说明。适用于任何消费者可见的集合，包括：

- interface、类型、record、dataclass、struct 或类的字段、属性与成员
- 枚举成员、字符串字面量联合类型成员，以及对象字面量映射或常量表的键
- 参数，包括解构或展开的选项对象
- 数据库表或迁移的列，以及序列化载荷的字段
- schema 声明的属性与元素
- 命令行开关、环境变量与配置键（写进 Markdown 文档而非声明处；见 [markdown-docs.zh-CN.md](markdown-docs.zh-CN.md)）
- 错误码、状态码，以及事件或消息名称

容器注释、描述性名称或类型标注都不能替代成员说明；成员没有说明就是未覆盖。适用时记录每个成员的语义角色、可选性/可空性、默认值、单位/范围、所有权/可变性、序列化/省略规则、生命周期、兼容性以及与其他成员的关系。对嵌套的消费者可见成员递归执行同样检查。

结束前先数一遍：一个有四个成员却只写了三处说明的集合，就是覆盖不完整——这是漏项，不是风格选择。可选成员要写明可选；声明本身没带默认值就写明默认值；类型本身表达不了单位时就写明单位——裸的 `number`、`int` 或 `string` 成员并不自解释。标记语言中无法给单个属性挂注释，因此把每个属性的一条说明写进所属的 JSON Schema、OpenAPI 或 XSD 文档；按成员覆盖的要求在那里满足。

使用编辑器能读取的形式。字段和成员要写语言的文档注释形式，而不是行尾注释，因为只有文档注释形式会出现在编辑器悬停中：TypeScript/JavaScript/Java 用 `/** ... */`，Rust 用 `///`，Python 用 attribute docstring（赋值语句下一行紧跟的字符串字面量）。行尾 `//`、`#` 或内联类型注释对悬停不可见，不满足本项覆盖要求。

说明简单且当前为单语时，注释保持一行，例如 `/** Per-request chunk ceiling in bytes. */`。双语模式下始终使用完整英语块、一个空行和完整本地化块，写在同一条注释内；不要把两种语言用分隔符压到一行。字段需要约束、默认值、关系或其他细节时扩展为更长的块。标记语言中，元素旁的 `<!-- ... -->` 是唯一可用形式，且编辑器悬停不会展示它；约束由 schema 所有时，写进 schema。

## 私有代码和实现覆盖

覆盖审查必须包含私有和内部代码以及导出符号。当某个实现代码块的**原因无法从代码中看出**时，就为它添加注释。判断以**参照读者**为准：他懂这门语言、懂这个业务领域，但不知道这段代码的历史。下列检验任一条成立，就要求写注释：

- **原因检验**——这位读者能否只靠代码、类型和仓库里的公开文档回答“为什么这样写”？答不上，就写。
- **改动检验**——把这行换成看起来等价的写法，行为会不会**静默**改变（不报错、测试也不失败）？会，就写。
- **预期检验**——这段是否偏离了朴素做法（更绕、更保守，或比看起来需要的更长）？偏离，就写清楚为什么。

不要把规模当作判据。行数、嵌套层数和圈复杂度两头都会出错：既会高估（一张又长又线性的查找表不需要任何注释），也会低估（一个没有说明的常量可能是全文件风险最高的一行）。一行的退避常量和一段带清理的有界重试循环，在这里属于同一类。

最常通过上述检验的情形，以及注释必须说明的内容：

- 调出来的阈值或魔数——为什么是这个值，换成别的会坏成什么样
- 不能调换的顺序——调换后会发生什么
- 为绕开上游行为或缺陷而写的代码——绕开的是什么
- 看起来可以简化、但其实不能的代码——更简单的写法为什么会失败
- 被吞掉、转换或重试的错误——这对调用方意味着什么
- 并发、重试、取消或清理——边界、顺序，以及它保护的状态

跳过简单包装器、直接赋值和显然控制流。先执行导出/私有覆盖检查，再对实现主体执行原因检查。

## 选择语法示例

读完本文件后，只阅读当前源文件需要的语法示例：

- [块文档注释（`/** ... */`）](comment-syntax-block.zh-CN.md)：TypeScript、JavaScript 或 Java
- [Rustdoc（`//!`/`///`）](comment-syntax-rustdoc.zh-CN.md)：Rust
- [Python docstring/注释](comment-syntax-python.zh-CN.md)：Python
- [标记注释（`<!-- ... -->`）](comment-syntax-markup.zh-CN.md)：HTML 或 XML

混合语言或未支持的格式使用最接近的语言/工具语法，并保持相同的语义覆盖和 `AGENTS.md` 策略。

## 验证

将每条注释声明对照实现、类型、测试、配置或明确假设验证。确认每个消费者可见可调用对象都覆盖参数/返回值/失败行为，且每个消费者可见成员集合中的每个成员都有说明。启用双语时检查两种语言的语义对等；
否则确认没有主动添加翻译。在可用时运行语言格式化、lint、类型检查或文档工具。

## 报告覆盖

改动结束时用一两行说明你记录了哪些、以及有意跳过了哪些并给出原因——例如：“已记录：`upload` 契约、`UploadOptions.chunkSizeBytes` 单位、重试退避。已跳过：`normalizeName`（简单透传）。”
在回复中说明，不要写进源码注释。这样覆盖决策对审查者可见，而不是藏在 diff 里。

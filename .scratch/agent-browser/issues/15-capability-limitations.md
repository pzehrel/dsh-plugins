# 15：能力缺失与下载限制反馈

**要实现：** 用户和 Agent 得到准确的版本/能力限制；遇到网页下载时明确停止该步骤，不报告生成了文件。

**阻塞依赖：** [01 官方增强独立装配与固定同页工具](01-official-browser-integration.md)

**状态：** done（固定通路完成，不代表首版整体通过）

**依赖说明：** 01；使用最小正式增强即可独立验证版本及不支持行为。

## 验收条件

- [x] 已验证能力按实际版本启用；缺失公开能力、平台或版本不匹配明确说明，不用历史证据冒充当前可用。
- [x] 在自有下载测试站验证 Agent 与人工路径受当前宿主限制，不通过私有接口、Host 匿名请求或另开浏览器绕过。
- [x] 下载不支持是已接受首版行为；完整 Network、断点、原始 CDP 和跨重启登录态也不显示为已支持。
- [x] 全局共享、上传、frame 等保留能力的缺失仍阻塞对应交付，不能借统一“不支持”提示把它们自动改成首版可选项。
- [x] 界面说明限于帮助用户判断下一步，不把内部协议和调试细节塞进浏览流程。

## 验证结果

官方 macOS Desktop `0.2.0-rc.2` 最终构建 `3b082962fd39`；人工与 Agent 下载限制通过；全局共享、上传、frame 等保留要求继续阻塞对应交付。见[验证报告](../../../plugins/agent-browser/docs/capability-limitations-validation.md)及其白名单记录。延迟、失败与缺失能力注入仅由受控回归证明，不冒充原生故障测试。

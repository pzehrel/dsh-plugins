# 02：跨工作区登录态可行性验证

**要实现：** 用自有测试站和两个不同工作区验证现有公开账号容器能力，给出 G2 的可行路径或可复查的阻塞结论。该任务不实现最终设置界面，也不预先承诺全局共享可行。

**阻塞依赖：** 无（可先推进）

**状态：** done

**可行性结论：** feasible

**依赖说明：** 无；复用既有固定版本调查与临时验证设施，不等待生产增强装配。

## 验收条件

- [x] 核对真实公开参数、版本及容器作用域；实际尝试跨工作区全局共享与工作区隔离，不能只根据同工作区进程分区推断。
- [x] 只用自有测试标记验证存储，不访问真实账号，不导出 Cookie，不伪造工作区身份或访问私有接口。
- [x] 如路径可行，提供可由 13 复用的公开契约及运行证据，验证不同容器、已有页面不变和会话权限独立。
- [x] 如路径不可行，明确哪些现有公开能力不能满足要求、尝试范围及影响；G2、13 和整体发布继续阻塞，不能自动改为工作区默认或删除目标。
- [x] 临时验证完成后撤销自身资源，保留必要的非敏感证据。

**主要覆盖：** G2 前置事实；A07；用户故事 24–28。

## 规格与实施边界

依据[首版实施规格](../../../plugins/agent-browser/docs/implementation-spec.md)、[领域词汇表](../../../plugins/agent-browser/GLOSSARY.md)及规格引用的 ADR。任务02已完成可行性验证；其他任务的依赖和完成状态仍按索引判断。

- 复用官方浏览器与统一页面控制边界，只补工具和必要交互；不修改 DSH 主程序、安装包或私有 IPC，不扩大自建浏览器。
- 权限来自真实 Agent 执行上下文及认证 Client 框架绑定，登录态共享不扩大页面权限。主验收边界是实际工具调用与同一可见共享页面结果。
- 固定测试页、替身测试和历史证据不代表完整产品通过。公开能力缺口保留为对应首版要求的阻塞，不擅自延期。
- 遵循仓库中文文档、ESLint、vitest 与统一门禁约定；记录实际版本、步骤、结果和未测项，不保存密码、Cookie 或控制凭据。
- 本轮已按用户授权执行任务02，不发布远端事项、不提交或推送代码，也不自动开始其他任务。

见[任务索引](../README.md)查看可推进项、依赖与共享完成条件。

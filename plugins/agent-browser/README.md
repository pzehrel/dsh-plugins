# Agent 浏览器

默认入口复用 DSH 官方内置浏览器源码、地址栏、标签、导航和样式，仅增加 Agent 页面工具、紧凑状态与人工接管入口。当前是预览版，完整首版仍有未完成项，见[任务索引](../../.scratch/agent-browser/README.md)。

## 安装与开始使用

在仓库根目录构建：

```sh
pnpm install --frozen-lockfile
pnpm --filter ./plugins/agent-browser run build
```

在官方 DSH 插件管理器中添加 `plugins/agent-browser/` 的绝对路径并启用，默认安装目录不是仓库根目录。安装后从官方浏览器入口或 `Cmd+T` 打开页面，应看到官方地址栏、标签和导航。根包直接装配官方浏览器增强；旧的“纯插件实验（Fetch v2）”面板不是当前入口。`dist/enhanced/` 指纹包使用同一实现，供需要独立构建身份的场景，只启用其中一个。

本地更新后若显示“工具版本不匹配”，先结束本轮验收，待其他活跃任务安全结束后正常退出并重开 DSH，刷新官方加载器缓存，再核对运行指纹。不要修改宿主或加载器，也不要为本次验收中断其他任务。维护者按[同一构建的交付流程](docs/verification.md#从检查到真实交付)完成检查与部署。

当前仅有获准 macOS 官方 Desktop 的限定验证，Web、其他操作系统、CLI 和第三方客户端未验证。选择可用 GPT 等模型，在当前会话中发送例如：

> 使用 agent_browser，在内置浏览器打开 https://www.wikipedia.org/，搜索 Hangzhou，实际点击词条中的 Prefecture-level 链接并读取新页面，然后后退确认 Hangzhou 页面，再前进确认目标页面。每次操作后重新观察，使用新引用继续；普通跳转不进行人工接管或交回。

原生点击、填写、按键和滚动都需要逐次审批。本次会话使用“工作区内修改”等可发起审批的模式；“完全权限”模式若将审批策略设为不询问，浏览器输入会明确拒绝，不能据此绕过确认。审批时核对目标与内容，允许一次后 Agent 才继续。逐次审批只批准当次输入，区别于会暂停页面 Agent 感知和操作的“人工接管”；普通跳转不需要接管再交回。

### 当前页面工具

工具名为 `agent_browser`。用 `list-tabs/create-tab` 取得本会话页面，`observe` 读取真实主文档及短期元素引用，再通过 `click-element/fill/press/scroll` 操作；导航、截图、基础控制台及获准文件上传沿用同一页面控制边界。`read/click` 是内部固定夹具动作，普通网页使用 `observe` 与原生输入。

正常点击、按键引发跳转时返回 `issued`，随后重新 `observe` 取得新页面与新引用即可连续操作，无需人工接管。导航最多等待一秒便返回实际加载状态；`loading=true` 时继续观察确认，不自动重发导航。真正的发送失败、取消或断线仍保留“结果不明”写屏障，不能冒充已撤回动作。

增强实现提供独立的页面内 Agent 指针：可见页移动到目标，后台跳过动画等待；会话结束时隐藏，接管或关页时撤销图形。指针穿透用户点击，不移动系统鼠标；纯视觉失败不会代替或取消正式输入许可。新动效的验证范围及当前边界见[独立指针反馈](docs/agent-pointer-validation.md)。

### 当前限制

后台选择既有标签、完整跨域 frame 和任意页面脚本仍有公开能力缺口。网页下载不支持；文件上传仅覆盖标准单文件、至 16 MiB、同页 HTTP(S) POST multipart 的限定切片，事件 `issued` 不代表网站接收成功。登录态范围配置、标签网址恢复及完整首版仍有未完成项，跨重启登录态与完整调试按已确认范围延期。

开发测试页和[旧实验记录](docs/spike-validation.md)仅用于内部验证。完整目标见[已确认首版范围](docs/design.md#已确认首版范围)与[任务索引](../../.scratch/agent-browser/README.md)，不能据历史切片推断全部能力已经交付。

## 已确认需求

- 在 DSH 侧边栏展示，保留原浏览器入口、侧栏布局、标签页、地址栏和导航样式；仅增加 Agent 指针、紧凑运行状态与暂停入口，审批复用 DSH 现有交互，不另造一套侧栏。
- 用户与 Agent 读取和操作同一个真实网页实例，保留登录态，用户能够手动接管。
- 独立后台浏览器加截图展示，不算完成上述共享页面要求。
- 优先服务登录后的日常网页任务，包括浏览、查资料、填写表单和点击操作。
- 仅面向官方 DSH Desktop，首版先针对当前 macOS 环境验收；其他操作系统实际验证后再声明支持，Web 不在本次范围内。此处是目标范围，不是已验证兼容声明。
- 侧栏必须承载原生可交互网页，不接受用实时画面流替代原生网页。
- 完整能力均纳入开发范围：页面文字和可交互元素、截图、导航、点击、输入、滚动、前进后退、多标签页、文件上传下载，以及脚本、控制台、网络调试。不能把日常任务优先解释为删除调试能力；采用下文已确认的分阶段实施顺序。
- 允许以新的原生页面替换浏览器实现，保留入口、侧栏位置和主要外观；无需迁移已经打开的旧页面，首次使用可重新登录。
- 登录态提供“全局共享”和“工作区共享”配置，默认全局共享；全局与各工作区使用独立账号容器。切换范围不自动复制 Cookie、不删除旧容器，已有页面不在中途更换账号。
- 每个 DSH 会话拥有自己的标签页，Agent 默认不能操作其他会话的页面；共享登录态不改变页面操作权限。
- 应用重启后保留登录态和标签页网址；不承诺恢复未提交表单，不自动重放之前的操作。
- 默认允许普通浏览；提交信息、发送消息、购买、删除等敏感操作先确认；脚本/CDP 与文件上传另外明确授权。审批不能完成时暂停，不自动绕过。
- 保留完整需求，现有公开能力不足的部分通过 DSH 上游正式接口扩展解决；插件与宿主工作分开，不修改安装包或调用私有接口绕过。

以上及下文规则由本轮 `/grill-with-docs` 的 Q1–Q20 确认（Q9 采用修订后的建议）；不构成实际访问账号、提交表单、购买或其他敏感操作的授权，也不代表现在开始修改 DSH 宿主。

## 人机操作方式

修订后的 Q9 已确认：普通浏览不要求先切换控制权，Agent 有独立指针、不移动系统鼠标；用户正常滚动不强制暂停 Agent。页面滚动或变化后，Agent 重新确认目标，不能盲用旧坐标。

提供可选的人工接管状态，在登录等敏感场景显式暂停该页的 Agent 感知与操作，交回后重新观察。独立指针不代表同一页面具有独立的滚动、焦点或表单状态；暂停不能撤回之前已发送给模型的内容或逆转已完成的操作。

需求动机来自用户对 Codex 的实测，具体来源边界见[调研记录](docs/research.md#codex-参考已验证与未知)，不将观察等同于对 Codex 内部实现的断言。

## 后台运行与页面关闭

Q14 已确认：收起侧栏、切换 DSH 会话不停止浏览器任务；明确关闭标签页才取消该页待执行操作。后台运行显示状态，不自动抢回用户当前查看的会话。

收起视图与关闭页面是不同动作。上述规则不意味着可以在用户关闭标签页后重建它来继续任务，也不意味着关闭页面能撤销已经完成的网站操作；接管、敏感操作审批和重启不重放的规则仍然适用。

## 文件传输与高级调试

Q15 已确认：上传前确认具体文件和目标网站；下载默认保存到系统下载目录下的 `DSH` 子目录，位置可配置，不覆盖同名文件，不自动执行下载文件。

Q16 已确认：读取页面、截图、查询控制台使用固定工具；任意脚本和原始 CDP 命令逐次确认，仅作用于当前 DSH 会话的标签页。“调试权限”不是其他敏感操作的通行证。插件内部为固定操作使用经过审查的实现，不等同于向 Agent 开放免审的任意脚本接口。

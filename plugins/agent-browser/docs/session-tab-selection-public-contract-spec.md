# 任务05：既有标签会话定向选择的公开接口需求

状态：本地需求规格；提出所需公开行为，不声明官方已经提供接口，也不授权修改宿主或发布事项。任务05及首版继续 blocked，13/14依赖不解除。本文补充[首版实施规格](implementation-spec.md)，不改变其产品范围。

## 问题陈述

用户在会话 B 查看并填写网页时，会话 A 的 Agent 仍需选择 A 已有的浏览器标签，以继续自己的多页任务。选择应保留原共享页面、文档和未提交输入；用户返回 A 时看到正确标签，当前 B 的页面、系统输入焦点和窗口保持原状。

固定旧版的原生验证已否定把原标签 contentId 直接交给 `openResourceIn` 的候选：browser 创建 `sidebar://browser/<uuid>`，资源入口只接受 `dsh-resource://`。候选受控绿例曾使用错误协议的替身地址；候选已撤回，现有离线契约回归固定了这项拒绝。公开方法存在、下游布局可以 focus，均不足以证明实际输入能到达该分支。详见[验证报告](session-navigation-validation.md)与[原生负例](evidence/session-navigation-public-route-verification.json)。

用户随后更新了 DSH。官方关于窗口确认运行版本为 `0.2.1-rc.2`；既有冻结构建曾因启动自测缺少新版必需的 Peer 参数而激活失败。本轮通过官方 `createPeer` 修复并在真实新版复验激活及注册200后，独立 Client 对自有既有标签的公开调用仍抛出地址不被认领的异常。历史激活失败与本轮实际选页拒绝分别保留，不能相互代替；见[诊断与复验证据](evidence/connection-peer-startup-0.2.1-rc.2.json)。

## 解决方案

所需能力是：通过正式公开契约，定向选择某个真实框架会话中已经存在的标签，并核验该会话的选中结果。选择以宿主提供的原标签身份和生命周期为依据，复用既有官方界面、布局及页面，不通过打开资源、转换地址协议或新建标签来代替。

新版复验优先于提出扩展必需性的结论。如果实际官方新版已存在满足全部条件的公开能力，插件可在验证来源、兼容性与原生行为后复用它；若仍无可用路径，本文作为能力需求保留。无论哪种结果，均不授权本仓库修改 DSH 主程序、安装包或私有 IPC，也不恢复已失效 ADR 的宿主开发路线。

## 用户故事

1. 作为用户，我希望后台 Agent 可以选择自己会话的既有标签，以继续多页任务。
2. 作为用户，我希望返回该会话时看到 Agent 选择的标签，以理解任务进度。
3. 作为用户，我希望另一个会话仍显示原页面，以继续当前工作。
4. 作为用户，我希望系统输入焦点保持在原输入框，以避免键盘内容落到别处。
5. 作为用户，我希望选页保留原页面实例和未提交内容，以避免丢失工作。
6. 作为用户，我希望选页本身不导航或刷新，以保留当前文档与网站状态。
7. 作为用户，我希望已收起的侧栏保持收起，以避免后台任务打断阅读。
8. 作为用户，我希望选页保留停靠与浮窗布局，以沿用官方界面。
9. 作为用户，我希望前台和后台采用一致的归属规则，以避免切换会话改变权限。
10. 作为 Agent，我希望目标来自本会话正式标签清单，以准确选择已有页面。
11. 作为 Agent，我希望确认本会话实际选中了哪个标签，以报告真实结果。
12. 作为用户，我希望相同 tabId 在不同会话中仍被分别核对，以避免串页。
13. 作为用户，我希望已经关闭的标签明确拒绝，以避免自动新建替代页面。
14. 作为用户，我希望重建后的同名标签不接受旧请求，以保留关闭操作的停止权。
15. 作为用户，我希望没有有效框架绑定或布局的会话明确报未就绪，以避免误用屏幕会话。
16. 作为用户，我希望人工接管期间 Agent 的选择请求被拒绝，以保持单页控制屏障。
17. 作为用户，我希望关页、取消和断线后的迟到结果不恢复旧目标，以避免任务复活。
18. 作为 Agent，我希望已选中的标签再次选择得到可核验的无变化结果，以避免多余副作用。
19. 作为用户，我希望共享登录态不扩大标签权限，以隔离不同 Agent 的页面操作。
20. 作为用户，我希望宿主缺少能力时得到明确限制，以判断任务为何停止。
21. 作为维护者，我希望接口有公开声明、版本和运行证据，以维护可复现的兼容边界。
22. 作为维护者，我希望依赖和宿主升级分别验证，以避免把旧 SDK 回归当作新宿主验收。

### 拟议公开能力的最小契约

以下均为需求，不是已存在的官方方法名、字段 schema 或错误码。具体公开名称与签名只有在官方声明和实现可核对时才确定。

1. **输入归属。** 插件从正式 Agent 执行上下文取得所属会话，再由认证 Client 的有效框架绑定核对。模型只能选择本会话已登记的目标，不能指定会话、工作区、窗口或 guest 取得权限。宿主选择能力负责核对指定会话内的目标；它不代替插件的 Agent 认证与页面控制。
2. **目标身份。** 选择绑定会话、既有 tabId，以及宿主公开提供的目标生命周期代次或等价短期句柄。tabId 是会话局部身份；地址、网址和同名 tabId 均不足以跨会话或跨重建识别页面。句柄只在框架与插件控制边界内流转，不作为模型提供权限的参数。
3. **纯粹选择。** 操作只改变目标会话必要的 active tab/pane，不创建或替换标签，不转换 contentId，不触发页面导航、刷新、恢复网址或重新获取 guest。已选中目标可成功报告无变化。
4. **布局与焦点。** 停靠结构、浮窗位置与大小、侧栏展开状态保持原状；不会切换屏幕会话、激活其他窗口或把隐藏会话的浮窗展示到当前会话。前台会话原布局、选中页和 DOM/系统输入焦点保持原状。
5. **可核验结果。** 成功须反映指定会话已提交的实际选择，关联原目标及其有效代次；插件能够在同一公开契约下核验，而不是读取当前屏幕的 active 标签推测后台状态。所需选择事实不要求附带页面标题、地址或正文。
6. **失败边界。** 未 adopted、绑定已释放、目标不存在、归属不符、代次失效或能力不可用时，在写入前明确拒绝；不回退前台 focus，不新建替代标签。若写入已发出但不能核验，结果保持不明，不自动重试或声称已回滚。
7. **竞态与生命周期。** 在提交边界重新核对目标。关闭与重建后的旧请求不能选中新实例；异步实现还须区分取消前未发出与发出后未确认。结束等待不自动证明宿主动作被撤回。

### 与既有插件控制边界的关系

正式工具、Connection 与统一 Broker 继续承担归属、执行许可、人工接管、取消、去重及最终结果交付。页面暂停时，session 锚点不能旁路页面屏障。若宿主选择操作仅改变布局且未更换页面或文档，插件也不能无故重建页面或把它当作重新授权。

网站自身的导航与动态变化仍可能发生；“选页不导航”只约束该操作本身。若在途发生文档变化、接管或绑定失效，既有页面/文档/暂停代次屏障仍负责拒绝迟到结果，不能用选页成功恢复旧引用或旧批准。

错误类别分层记录：宿主提供未就绪、目标失效、不支持及选择提交的确定性事实；插件继续解释本会话权限、人工接管、审批和请求取消。二者合并后仍须准确区分未发出、已完成、无变化及结果不明，不把宿主的同步返回视为全部工具流程通过。

## 测试决策

### 沿用已确认的边界

最高验收边界仍是“真实 Agent 调用工具 → 官方 Desktop 中同一共享页面出现结果”。内部沿用统一页面控制边界和刚补齐的真实公开侧栏契约回归；拟议能力只成为宿主适配的公开接缝，不新增另一套浏览器控制通道。测试观察外部行为，不依赖 React 私有结构、压缩变量名或 Electron 私有对象。

既有回归已说明：真实官方创建地址和入口检查必须执行；把宿主服务整体替换成按预期成功的假实现，会掩盖协议缺口。内存框架、渲染和持久化介质替身只能用于受控回归，不证明原生焦点、页面保活或平台兼容。

### 新版复验与能力验收

| 阶段 | 必须取得的证据 | 未通过时的处理 |
| --- | --- | --- |
| 新版基线确认 | 后续原生复验记录实际运行的宿主版本、构建指纹、SDK 与公开声明；区分已安装和运行中。 | 新版保持未验证，不迁移旧结果或假定旧构建兼容。 |
| 现有公开能力复验 | 只用自有页面与会话，先核对实际创建身份及真实公开入口，再判断新版是否已有满足所需行为的公开能力。 | 原始拒绝、未到达入口及能力缺失分别保存；未发现可用路径时保留本需求。 |
| 定向选择正例 | A 有两个已有页，B 正在输入；A 实际工具选择旧页后标签集合、tabId/contentId、页面实例及文档标记保持，B 真实键入仍落在原输入框。 | 任一身份变化、重载、新建或焦点抢占均不能算成功。 |
| 反向与布局 | A/B 交换前后台；覆盖目标已选中、侧栏收起、停靠与浮窗，均核对各自选择及页面状态。 | 有限单向或停靠结果不扩大为全部场景支持。 |
| 归属与重建 | 双向跨会话 pageId 拒绝；局部 tabId 重名；目标关闭、重建、绑定释放及其他窗口目标明确处理。 | 不要求相同字符串在所有会话都无效；要求实际归属与目标代次正确。 |
| 控制与迟到结果 | 接管前拒绝，在途接管/取消/关页/断线后旧结果不交付；交回后重新观察，不重放旧请求。 | 维持既有 Broker 屏障；不得仅凭布局成功解除接管门槛。 |

每次原生记录须区分真实 Agent 工具调用、独立 Client 公开探针和受控测试。审批只有实际触发并观察到界面与结算时才计入证据；驱动标签中的通用名称不构成证明。仅操作本轮自建资源，不访问真实账号、不运行模型自主步骤，也不处理已有后台 Agent。

只有新版来源、兼容、选择和相关控制证据通过，才可据其范围推进任务05。即使后台选页切片通过，任务05其余导航与完整原生条件仍须分别满足；09、12以及 G4/G5、16和首版也不会由此自动通过。

## 范围外

- 本轮不实现或提交宿主接口，不修改主程序、ASAR、私有 store、IPC 或 CDP，也不增加自建浏览器。
- 规格整理阶段不升级仓库 SDK、浏览器归档、锁文件或回归基线，不安装插件或操作原生页面。后续限定复验的临时安装与实际结果单独记录，不作为产品修改授权。
- 不要求迁移 builtin 旧页，不用资源新建、网址重开或独立浏览器替代原页选择。
- 不缩减跨域 frame、页面脚本、登录态范围或首版要求，不把其缺口并入本接口来扩大设计。
- 不发布远端事项、上游请求或 PR，不自动提交或推送。本地规格不赋予 ready-for-agent 或已交付状态。

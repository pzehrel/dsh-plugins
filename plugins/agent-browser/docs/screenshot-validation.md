## 公开能力与输出

匹配 SDK `@deepseek-ai/dsh-attachment@0.2.0-rc.2` 的公开声明提供 `AttachmentStore.saveImage({ data: Uint8Array, mediaType, name? })`，返回 `ImageAttachmentRef`。正式工具输出采用 `{ type: 'image', attachment: ref }`，同时给出页面、文档、去除用户信息/查询/片段后的展示网址及信息暴露说明；不以data URL、本地文件路径或伪造附件身份代替成功。

图片存储通过正式Cordis的 `ctx.inject(['attachments'], ...)` 子作用域接入。服务不存在或解除时只停用后续截图保存，不阻断核心固定工具；解除服务先撤销新保存句柄，其子作用域清理与统一Host请求登记均等待已开始保存结算，解除服务不代表保存已经取消。SDK对象式inject是服务名到配置的映射，不存在required/optional声明形状。

图片引用的字段由该SDK定义：`attachmentId`是不可当作路径的存储身份，`mediaType`是存储验证后的媒体类型，`bytes`为编码字节数，`width`和`height`为像素尺寸；可选`name`只作显示，可选`originalDimensions`记录缩小前的宽高。实现见[截图类型与捕获](../src/screenshot.ts)和[Host保存适配](../src/screenshot-host.ts)。公开原生方法仍须在实际版本验证，方法存在不等于平台验收通过。

原始URL只在当前请求栈内核对变化，传输及结果元数据不保留username、password、query或fragment；路径仍可能含网站自行编码的信息，截图本身也可能显示这些文字，未声称通用像素脱敏。

Client只对自己持有的同一guest调用一次 `capturePage()`，不创建同网址副本、不持续录屏、不保存截图缓存。传输仅接受最大4 MiB的PNG字节，Host再由真实附件存储验证图片。能力缺失、捕获失败、编码无效及附件服务缺失均明确停止；不交付旧图或替代页面。

保存采用两个阶段：Host先检查当前请求并保存图片，再由Client重新核对原guest、文档、网址和许可；最终Host只交付自己为该请求保存的引用。存储期间导航后的旧图片不会交付给Agent。截图不解除交回后“先新观察再写入”的屏障。

截图与语义观察统一使用 Client 私有 `documentId`。网页可见的根标记仅供前后复核，不是授权身份；公开导航事件推进私有代次，即使同文档导航保留相同网页标记，保存中的旧图和旧元素引用也会拒绝。

## 接管、取消与留存边界

接管在任何await前阻止新的Client操作。已开始捕获必须结算；返回后许可已经失效便不传输、不开始保存。已开始的 `saveImage` 没有取消信号，也没有公开删除方法；Host的pause、close及卸载等待真实保存结算，Client同时等待原生操作及请求结算，才能显示 `paused` 或完成关闭。只取消RPC而不等Host保存不能算接管生效。

接管生效后不再开始捕获或保存，也不补发旧结果。`pausing`仍表示正在等待，不能作为隐私屏障已经成立的提示。接管前已开始保存的图片可能在等待期间落盘；导航、取消或关闭使结果失效时，该附件也可能已经存在，但引用不会交付。实现不承诺删除已经保存的附件，未把丢弃迟到引用表述为擦除磁盘。此限制须与规格的接管要求一起验收，不能升级成“图片从未留存”的结论。

## 信息暴露限制

截图包含全部可见像素，普通DOM文字过滤不会对PNG脱敏。当前固定检查在捕获前后发现密码输入、密码/一次性验证码/银行卡相关autocomplete、显式`data-private`输入或frame时拒绝截图，不尝试通过隐藏字段后输出原像素。frame的像素边界尚未证明，因此保持拒绝并明确说明。

该检查不能证明普通文字、图片、画布、shadow DOM、动态短暂内容或其他输入不含秘密，也不能原子地冻结任意网页内容。工具说明与成功结果明确提示这一限制；敏感页面应先人工接管处理。当前没有声称截图已普遍脱敏，或任意网页均安全；本次真实guest敏感字段及frame拒绝行为见下方原生记录，不能外推任意网页均已脱敏。

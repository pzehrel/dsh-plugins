# 跨工作区登录态范围：任务02验证

结论：在官方 macOS Desktop 与浏览器包 `0.2.0-rc.2` 上，使用公开 `DesktopBrowserBridge.acquire` 为插件自己的存储账号分配分区，可以实现跨真实工作区的全局共享，以及各工作区的独立容器。任务02的工程可行性验证完成，已取得任务13所需的正面证据；正式范围设置与完整首版 G2/A07 验收仍待任务13等后续工作完成。

本轮未访问真实账号，未发送模型消息，未修改 DSH 主程序、安装包或私有 IPC。实际过程及摘要见[原生证据](evidence/login-scope-verification.json)，产品要求见[首版实施规格](implementation-spec.md)。

## 公开契约与实现的区别

官方[公开类型](https://cdn.jsdelivr.net/npm/@deepseek-ai/dsh-client-ui-sidebar-browser@0.2.0-rc.2/lib/types/types.d.ts)声明 `acquire(workspace: string)`，参数注释为 `resolved storage account`。它接受已解析的存储账号，没有在该声明中限定必须是 Workspace 记录 ID 或 `cwd:` 字符串。官方[浏览器说明](https://cdn.jsdelivr.net/npm/@deepseek-ai/dsh-client-ui-sidebar-browser@0.2.0-rc.2/README.zh.md)描述的按规范化 CWD 分组，是 builtin 浏览器自身的账号解析策略；该插件没有全局范围设置字段。

静态核对表明，当前主程序按传入账号字符串映射进程内分区，并为每个 guest 单独发租约，检查所属窗口及分区一致。当前安装包的主进程文件与本次分析的只读副本逐字节一致；REA 分析记录为 `ev_6d5bd81fa6604773c1fb03c877708db880f7df450aa20edaa3c845110b1e6ab2`，摘要为 `ev_3ae4bafe2bce67f6c733ad73e36278d6747699cc794898586a74e080c988a472`。语义图因节点上限为部分覆盖，不用其未观察到的关系证明“不存在其他路径”，也不以静态结果替代运行验证。

因此，本次验证的是公开 bridge 能否承载插件自有账号命名策略，不是宣称 builtin 已有全局配置，也不是把任意字符串测试当作正式支持证明。真实数据结果如下。

## 验证方法

沿用已验证的固定官方浏览器增强、既有实验 Host、正式 Connection 和自有 loopback 测试页。只额外增加临时账号解析与诊断，不重写浏览器 UI。

- 工作区 A 为本仓库；B 为本次创建并由官方 UI 正式登记的临时目录。两个规范 CWD 的摘要与 Host 观察一致，确为不同真实工作区。B 使用宿主创建的草稿会话，无需发送消息。
- 框架 `workspaces.list` 仍解析真实会话归属；真实工作区和工具权限身份从未回写或替换。插件自有账号使用本次独立命名空间：全局账号相同，工作区账号再关联真实工作区来源。这些账号 key 不伪装成另一个工作区 CWD，也不是控制凭据。
- 默认选择全局账号。切换诊断范围只影响之后初始化的页面；官方页面生命周期缓存本页已解析账号，旧页不换容器。
- 三个全新账号分区中，仅写入一个本次 Cookie 键和一个 localStorage 键，值限定为 `A`、`B`、`C`。诊断只返回这两个自有键，不导出完整 Cookie、storage 或账号数据。
- 控制凭据只经原正式 Host/Client 通路流转，不注入 guest。页面仅有既有测试字段和证据文本，诊断读取固定命令而不接受任意脚本。

## 真实结果

| 场景 | 观察 | 结论 |
| --- | --- | --- |
| 默认全局跨工作区共享 | A 的全局页最初为空，写入 A；B 的全局页 Cookie 和 localStorage 均读到 A。工作区摘要不同、账号摘要相同。 | 通过。 |
| 不复制全局账号数据 | 切换工作区范围后，B 的新容器为空，再写 C；A 的新容器仍为空，再写 B。 | 通过。 |
| 同工作区共享、跨工作区隔离 | A 的另一个工作区页读到 B，B 的工作区页维持 C。两个工作区账号与全局账号均不同。 | 通过。 |
| 旧页不换号 | 切换范围后，旧全局页重新读取仍为 A。切回全局后，旧 A 工作区页仍为 B、旧 B 工作区页仍为 C。 | 通过。 |
| 原容器未被切换删除 | 切回全局后新开的 A 页仍读到 A。 | 通过。 |
| 会话页面权限不随账号共享扩大 | 两个真实 Agent 经公开 `ToolRuntime.execute` 读取各自固定页成功，交叉读取均被既有 Host 明确拒绝；两个方向都验证。 | 通过。 |
| 清理 | 三个容器的自有 Cookie/localStorage 键均清空，6 张临时页关闭，临时包卸载，诊断监听明确拒绝连接。 | 通过。 |

工具权限验证使用真实执行流水线及真实框架 Agent，不是模型自主调用证明。完整多标签、所有窗口组合及生产工具权限仍按任务05和最终验收执行。

## 复现与自动检查

在仓库根使用已安装依赖执行：

```bash
node tools/prepare-login-scope-probe.ts
```

命令不接受参数。它复用固定版本下载与 SHA-512 校验，输出临时目录、诊断组合包、工作区 B 目录及构建摘要。不会自动安装、修改 profile、注册工作区或操作 Desktop；`nativeDesktop` 始终先标为 `not-verified`，生成产物不等于原生通过。MIT LICENSE 保留在组合包内。

真实复现须先在当前官方 Desktop profile 加载既有实验 Host，并确认其当前固定测试站就绪，再通过官方插件管理器本地加载输出的组合包。在 A 和由官方 UI 登记的 B 工作区，用原浏览器入口打开 Host 当前给出的固定测试网址。不要用历史端口当作当前就绪证据。

测试页的“人工修改内容”可输入以下固定诊断命令；它们是一次性验收设施，不是产品 UI 或模型工具参数：

| 命令 | 行为 |
| --- | --- |
| `scope:read` | 读取本页容器的两个自有测试键。 |
| `scope:write-A`、`scope:write-B`、`scope:write-C` | 只将本次自有 Cookie/localStorage 键写成对应单字符。 |
| `scope:global` | 后续新页使用本次插件全局账号，已有页不变。 |
| `scope:workspace` | 后续新页使用关联真实工作区的账号，已有页不变。 |
| `scope:owners` | 通过已登记的两个自有页面与真实 Agent 检查本页读取和交叉拒绝；没有有效结果时不得算通过。 |
| `scope:clear` | 仅清除当前账号容器中本次创建的两个键。 |

依次复现表中的三账号读写与切换场景，最后在三个账号容器分别清除自有键，再关闭全部临时页、移除临时工作区关联并卸载组合包。

自动回归覆盖账号解析边界：默认全局跨工作区共享且保留真实来源、工作区账号相互隔离并与全局分开、没有真实工作区绑定时拒绝。另有正式 Connection 加真实 loopback HTTP 的回归，验证报告只白名单输出自有值，丢弃附加字段并拒绝未知范围或动作；这些回归也先失败后通过。上述测试不证明 Electron 的真实持久化行为，真实结果来自上表及证据记录。最终门禁另报告实际执行数，固定官方产物组合测试未准备时的跳过不能算通过。

## 清理与限制

本次临时包已从官方管理器卸载，工作区 B 已从列表移除，原实验入口保留。官方“删除工作区”只移除列表关联，保留文件夹和会话记录；本次没有删除用户原有会话。四个 profile 配置文件与实验前逐字节相同，安装包 ASAR 摘要不变。

所有临时 guest 与控制凭据均随关页释放，诊断服务与精确路由随卸载撤销。公开 `release` 不提供删除主进程分区映射的能力，因此空分区记账可能保留到进程结束；自有数据已经清空，没有为此调用私有清理接口。

临时产物路径与摘要仅用于追溯本次观察；目录可能被系统清理，历史 JSON 也不能作为未来一次验收的通过证据。

## 复核后的报告边界补强

独立规范复核发现诊断 Host 原先会保留 `value` 的未声明附加字段。当前源码已改为白名单投影，并限定范围、动作及测试值；通过正式 Connection 和真实 HTTP 报告读取的回归证明附加内容被丢弃、未知范围/动作被拒绝。

本次原生证据来自证据文件所列摘要的临时产物，未覆盖或重写该产物。19 条实际观察仅含预定的自有标记字段，未包含额外网页数据。报告补强不改变存储账号或 bridge 路径，其后由协议/HTTP 回归验证，未为此重复安装和运行整套 Desktop 实验；原生分区结论与补强后的报告边界证据分别记录。

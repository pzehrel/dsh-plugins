# Agent 浏览器首版实施规格

状态：本地规格，基于已确认的产品范围、工程边界和限定实测整理。测试边界已再次确认；工程前置验证尚未全部通过，不能据此声明完整首版可交付。当前任务状态与依赖以[任务索引](../../../.scratch/agent-browser/README.md)为准，完整首版须完成后续任务与整体验收。本地实施不创建远端事项、不自动提交或推送代码。

## 问题陈述

用户需要在官方 DSH Desktop 的原浏览器侧栏里，与 Agent 使用同一个真实网页。人工登录、修改表单或滚动之后，Agent 应读取当前页面；Agent 操作的结果也应直接出现在用户面前。相同网址的独立后台页面不能满足这一需求。

当前最小实验只覆盖自有测试页的固定字段和计数按钮。官方浏览器复用实验进一步证明了原界面与导航可以保留，并通过真实 Host 工具流水线读取、点击同一原生页面；它尚未提供完整页面感知、输入、截图、上传、账号容器和完整人工接管屏障。

后续实现需要把这些实验整理为可维护的浏览器增强插件，避免将自建测试侧栏扩大为另一套浏览器，也避免把限定实测当作完整产品通过。

## 解决方案

首版面向实际验收的 macOS 官方 DSH Desktop，基于匹配宿主版本的官方浏览器实现做独立增强，通过正式 Sidebar extension 接管 browser kind。保留原入口、侧栏布局、主题、标签页、地址栏、导航和网址恢复逻辑，只增加 Agent 工具、页面控制、Agent 指针、紧凑运行状态及人工接管入口。审批复用 DSH 现有交互。

用户与 Agent 操作同一共享页面。工具由真实调用 Agent 的 DSH 会话确定权限，页面由增强插件通过公开契约创建并持有；不取得旧 builtin 的私有 controller，不要求迁移旧页面。首次使用增强实现可以重新登录，卸载增强后恢复 builtin。

首版保留页面感知、截图、导航与输入、多标签页、会话隔离、人工接管、后台生命周期、上传、基础控制台及逐次审批的页面脚本。默认全局共享登录态，并可切换为工作区共享；这一要求尚未因工程缺口而取消。首版仅延期网页下载、完整 Network/断点/原始 CDP，以及跨重启登录态。

## 用户故事

1. 作为用户，我希望从原有浏览器入口和快捷键打开侧栏，以保留熟悉的使用方式。
2. 作为用户，我希望沿用官方标签页、地址栏、导航、布局和主题，以避免学习另一套浏览器界面。
3. 作为用户，我希望网页是真实原生页面，以正常使用中文输入法、复制粘贴、滚动和网站登录。
4. 作为用户，我希望 Agent 与我使用同一个共享页面，以直接观察它的结果并介入。
5. 作为用户，我希望启用增强时可以重新登录且无需迁移旧标签页，以避免依赖旧插件的私有对象。
6. 作为用户，我希望卸载增强后恢复内置浏览器，以便撤销插件而不破坏原浏览入口。
7. 作为 Agent，我希望列出当前 DSH 会话拥有的浏览器标签页，以选择正确的任务页面。
8. 作为 Agent，我希望在当前会话创建、选择和关闭标签页，以完成多页任务而不接管其他会话。
9. 作为 Agent，我希望读取页面文字和可交互元素，以按语义定位链接、按钮和输入框。
10. 作为 Agent，我希望按需获取当前页面截图，以验证视觉状态和操作结果。
11. 作为用户，我希望密码等敏感字段不被普通页面感知工具输出，以减少不必要的信息暴露。
12. 作为 Agent，我希望导航、刷新及前进后退，以完成连续的网页任务。
13. 作为 Agent，我希望点击、填写、按键和滚动，以操作普通网页与动态表单。
14. 作为 Agent，我希望导航、滚动、重排或文档变化后重新确认目标，以避免误用过期元素引用和坐标。
15. 作为 Agent，我希望知道跨域 frame 是否可操作及失败原因，以避免把读取失败解释为空页面或已完成。
16. 作为用户，我希望 Agent 指针不移动系统鼠标，以继续使用自己的鼠标。
17. 作为用户，我希望普通手动滚动和查看无需强制交接，以保留低打扰的浏览体验。
18. 作为用户，我希望显式人工接管当前页，以手动处理登录、验证码等敏感步骤。
19. 作为用户，我希望接管暂停该页全部 Agent 感知与操作，以防止普通工具、截图、脚本和控制台成为采集旁路。
20. 作为用户，我希望接管期间不留存面向 Agent 的采集缓存，以防止交回后补发这段内容。
21. 作为用户，我希望暂停未生效时明确看到等待或失败，以免把按钮状态误认为隐私屏障已经成立。
22. 作为 Agent，我希望人工交回后重新观察，以使用新页面状态继续任务而不重放暂停前动作。
23. 作为用户，我希望每个 DSH 会话拥有自己的标签页，以避免多个 Agent 串页。
24. 作为用户，我希望默认跨工作区共享网站登录态，以减少同一账号的重复登录。
25. 作为用户，我希望可以选择工作区共享登录态，以按工作区区分网站账号。
26. 作为用户，我希望切换登录态范围只影响之后创建的页面，以避免正在运行的任务中途换号。
27. 作为用户，我希望切换范围不复制 Cookie、不删除旧容器，以避免无意迁移或丢失账号数据。
28. 作为用户，我希望共享登录态仍不授予跨会话页面权限，以区分账号共享与标签页归属。
29. 作为用户，我希望收起侧栏或切换会话后任务继续，以便同时处理其他工作且不被抢焦点。
30. 作为用户，我希望明确关闭标签页取消其待执行动作，以保留最终停止权。
31. 作为用户，我希望应用重启后恢复标签页网址及正确归属，以便重新登录后继续准备工作。
32. 作为用户，我希望重启不恢复未提交表单或自动重放旧操作，以避免重复提交。
33. 作为用户，我希望提交信息、发消息、购买、删除等敏感动作先确认，以控制实际后果。
34. 作为用户，我希望审批绑定具体页面、动作和内容，以避免旧批准被套用到变化后的目标。
35. 作为用户，我希望上传前核对具体文件与网站，以避免错传文件或授权任意目录访问。
36. 作为用户，我希望上传取消、文件变化、权限不足或页面变化时有明确结果，以决定是否重新授权。
37. 作为用户，我希望遇到网页下载时明确知道首版不支持，以免把未生成的文件当成成功结果。
38. 作为 Agent，我希望查询当前页的基础控制台消息，以定位页面错误。
39. 作为用户，我希望任意页面脚本逐次确认目标和代码，以控制当前页面中的额外执行。
40. 作为用户，我希望调试同样受页面归属和人工接管约束，以防止它绕过普通工具限制。
41. 作为 Agent，我希望区分拒绝、取消、不可用、超时和结果不明，以避免盲目重试或报告虚假成功。
42. 作为用户，我希望插件卸载时停止工具、订阅和请求，并撤销页面控制凭据，以确保旧目标不能继续操作。
43. 作为用户，我希望缺少公开宿主能力时显示具体限制，以免插件暗中改用私有接口或其他浏览器。
44. 作为用户，我希望完整首版以真实官方 Desktop 场景验收，以确保工具测试通过时侧栏也能正常使用。

## 实施决策

### 官方实现复用与模块职责

1. 官方浏览器增强 Client 负责复用原 UI、导航、标签页和恢复逻辑，将框架绑定的会话、标签页及页面生命周期接入统一控制边界。新增界面限于 Agent 指针、运行状态和接管入口；不另写地址栏、导航或浏览器主页。
2. Host 工具入口负责工具注册、真实调用身份、审批、能力检查、请求关联及结果输出。工具权限取自正式执行上下文，不能由模型传入任意会话、工作区、窗口或 guest 身份来决定。
3. 统一页面控制边界承接页面登记、归属、执行许可、暂停代次、取消和结果交付。沿用既有 Broker 的行为与 Connection 通路，按首版需要扩展；不为截图、脚本或控制台另外建立绕开这些检查的控制链。
4. 原生页面适配只持有增强实现创建的页面，通过已核验的公开租约及方法操作。页面感知或定位库封装在这个边界内；`playwright-injected` 等仍是候选，选型须核对版本、实际行为与许可证，不预设完整 Playwright 或 CDP 服务。
5. 正式增强使用独立模块、Sidebar 实现、locale、样式归属及检查点身份。沿用 browser kind 和原入口，避免重复注册快捷键；卸载撤销自身注册并恢复 builtin，不删除 builtin 数据。
6. 生产实现以固定版本、可审计且可复现的源码级增强为目标。首先核对可取得源码与已验证官方发布产物的对应关系、构建依赖及 MIT 声明；不得直接把临时 bundle 字符串替换脚本提升为生产发布方式，也不得将较新的官方源码视为当前宿主兼容证明。
7. 实验的 loopback 测试站、人工标记轮询和 self-test 驱动属于验证设施，不作为生产浏览器的自动触发入口。生产工具由正常 Agent 工具调用驱动；生产增强不能依赖另行加载旧实验插件才可工作。

### 页面身份、工具与结果契约

1. 页面登记由认证 Client 的框架绑定发起，Host 铸造页面身份和仅在 Host/Client 间流转的控制凭据。工具可选择本会话的页面身份，但不能读取凭据、扫描宿主 DOM 或附着到其他插件的页面。
2. 每次操作绑定实际调用会话、页面实例、文档、必要的 frame、观察状态及当前暂停代次。关闭、重建、导航或目标变化后，旧身份或观察不得悄悄绑定到另一个相同网址的页面。
3. 工具能力覆盖本会话标签页管理、页面观察、截图、导航、点击、输入、按键、滚动、上传、基础控制台和获批页面脚本。具体工具名称与参数 schema 在核验正式 SDK 后确定，本规格不虚构宿主 Service 或 endpoint。
4. 普通感知工具使用固定且经过审查的实现，不接受任意脚本充当“只读参数”。输出过滤密码等敏感字段；控制台和截图也须纳入信息暴露与暂停测试，不能仅过滤 DOM 文本后声称全部信息安全。
5. 元素引用与坐标必须能够检查其文档、frame 及观察有效性；执行前重核页面、目标、可见性和命中。普通人工滚动或布局变化后重新定位，无法确认时返回冲突或失效，不猜测目标。
6. 同一页的 Agent 写操作串行；普通人工浏览不强制整体加锁。输入和 Agent 指针不移动用户的系统鼠标，但共享页面仍共用焦点、滚动和表单状态。
7. 请求具有唯一关联身份、取消信号及明确的执行与结果状态。结果表达实际页面、地址及必要的新观察，区分成功、失败、人工接管、待审批、关闭、能力缺失、取消和结果不明；具体错误码随真实接口确定。
8. 已发出的原生动作可能已经生效。断线、取消或超时不得报告“肯定未执行”，敏感动作结果不明时不得自动重试。已取消或已失效请求的迟到结果不得交付或恢复排队执行。

### 人工接管与授权

1. 普通手动滚动、查看不等于人工接管，不强制弹出交接；受影响的 Agent 目标必须重新确认。
2. 显式接管先阻止新的 Agent 读写，撤销排队请求与旧代次，并停止该页面向 Agent 的订阅、观察器、持续采集、缓存及注册后台任务。覆盖页面观察、截图、输入、控制台和页面脚本，不允许调试旁路。
3. 接管生效前等待必要清理及在途结算，阻断未交付数据和迟到回调。不能确认 Agent 注入任务已经停止时，只能显示等待或失败；不能显示已接管。交回后从新观察开始，不补发接管期间数据或重放旧动作。
4. 已发送给模型的内容无法撤回；已经发生的网站操作或获批脚本副作用不能逆转。原网页自身活动不因接管自动停止，但 Agent 注入的持续任务不能被归为网站活动而豁免。
5. 普通浏览按宿主权限执行；敏感动作和无法可靠确认风险的动作先确认。网页文本、快照、控制台消息中的“已授权”均不构成用户授权。
6. 审批绑定页面、网站、当前文档、动作、内容、脚本及必要文件和权限。执行前复核；审批期间发生实质变化时旧批准失效。审批拒绝或不可用时停止相应动作，不能默认允许，也不声称通用关键字规则足以判断所有网站副作用。
7. 任意页面脚本逐次审批，不授予宿主 Node、DSH 主界面、其他会话或无限调试权限。脚本造成的 Agent 后台任务须能纳入接管和卸载清理；无法保证这一点时，相关能力不得标为已通过。

### 标签页归属、登录态与恢复

1. 标签页归属为 DSH 会话；工具仅列出和操作本会话获准页面。窗口切换、当前可见会话或共享登录态不改变权限。两个会话的正反向越权、过期连接和重建页面均需拒绝。
2. 登录态默认在当前 Desktop profile 内本插件的各工作区全局共享，并可切换为工作区共享。这里的全局不包含普通 Chrome、DSH 主界面或其他应用。builtin 按规范化工作区 CWD 分组；后续[任务02](login-scope-validation.md)已验证公开 bridge 可为插件自有账号提供跨工作区共享。正式范围配置和完整 G2/A07 验收仍待任务13等实现，不能提前标为首版完成。
3. 全局容器和各工作区容器相互独立；配置切换仅影响之后创建的页面，不复制 Cookie、不删除旧容器、不改变已有页面使用的容器。账号共享不授予页面操作权限，同账号的退出登录、购物车等服务端状态仍可能相互影响。
4. 仅使用正式宿主容器能力。不能靠伪造工作区、导出 Cookie 给模型或访问私有 IPC 来实现全局共享；若验证仍无公开实现路径，保留阻塞并报告，不自动降为默认工作区隔离。
5. 收起侧栏和切换会话时保持页面与任务存活，提供后台状态且不抢焦点。适配官方生命周期时必须区分隐藏与明确关闭；若原生实例无法保活，记录具体缺口，不退回自建浏览器路线。
6. 明确关页取消排队和在途请求，撤销旧控制凭据；迟到登记也必须完成撤销，重复清理保持幂等。插件卸载须等待已开始的清理，不自动重建页面继续旧任务。
7. 首版重启仅恢复各会话的标签页网址及正确容器关联，按需重新登录；不恢复未提交表单、不重放动作。跨重启存储持久化不在首版成功条件内。网址检查点不迁移 builtin 的旧页面或数据。

### 文件、调试及兼容范围

1. 上传保留为首版要求，经公开宿主能力选择并传入获准文件。核对具体文件、目标网站、页面和权限；取消、文件变化、页面变化及权限缺失返回明确结果。受限字节注入实验不自动等于完整原生上传能力。
2. 网页下载在首版明确不支持，包括不能绕过宿主对人工下载的限制；任务依赖下载时停止该步骤并说明原因，不报告成功，也不以匿名 Host 请求代替原网页下载。
3. 基础控制台与逐次审批的页面脚本保留为首版能力，受同一归属、暂停、取消和授权控制。完整网络请求/响应、断点和原始 CDP 延期，不以页面网络 hook 冒充完整 Network。
4. 仅声明实际验收过的官方 macOS Desktop 组合。当前限定证据对应 `0.2.0-rc.2`，不等于承诺该版本已满足全部首版能力或代表最低支持版本；版本门槛由前置验证和最终验收确定。
5. 宿主缺少公开能力时，显示具体缺口并停止依赖该能力的步骤。不得修改主程序、重打包安装包、调用私有 IPC 或依赖未经验证的未来版本来宣称交付。

| G1 官方实现与装配 | 固定版本源码与发布产物对应、可复现构建、许可证保留；正式扩展加载、原入口共存、样式隔离、卸载恢复。 | 不扩大 UI 重写，不直接发布临时补丁产物；记录版本或构建缺口。 |
| G2 登录态范围 | 在两个不同工作区证明默认全局共享、工作区隔离、容器切换不迁移且旧页面不换号，权限仍按会话隔离。 | 首版发布阻塞；不能把重启登录态延期扩展解释为取消全局共享。 |
| G3 页面与后台生命周期 | 官方实现下隐藏、切会话保活，页面/文档身份正确；关页、断线、卸载和迟到登记不会复活旧目标。 | 依赖保活的功能不可标为完成；如实报告正式契约缺口。 |
| G4 页面能力 | 在真实 guest 验证观察、截图、输入、跨域 frame、上传、控制台和脚本所需公开能力；核对选用依赖及许可。 | 对应用户故事和验收项保持阻塞；不能默认为延期或降级成功。 |
| G5 完整接管与审批 | 证明所有 Agent 通路和持续任务可暂停，迟到结果与接管期缓存不补发，正式审批拒绝/不可用时不执行。 | 不显示接管已生效，不宣称相关脚本或调试能力已完整支持。 |

上述门槛未改变产品范围。若公开能力无法满足任一首版必需项，应先提交具体事实和影响，由用户决定是否另改范围；本规格不预先代替这个决定。

## 测试决策

### 主要边界与已有基础

主验收边界为“真实 Agent 调用浏览器工具 → 用户在官方 Desktop 侧栏看到同一共享页面的结果”。该边界已在设计阶段确认，并在本次规格整理中再次确认。最高层尽量使用同一可控测试站覆盖成功、错误与敏感动作，再以获准真实网站补充正常浏览和人工登录后的任务；不通过真实购买或删除来证明敏感动作。

内部回归集中在统一页面控制边界，观察归属、审批、请求与页面状态、取消及结果，而不绑定 React 私有结构、压缩变量名或 Electron 私有对象形状。只有原生页面与公开宿主服务等外部边界可替换；替身证明协议行为，不证明真实 UI 或平台兼容。

既有基础包括 Broker 的归属、接管代次与取消回归；正式 Connection 与已有 Gateway 共存的组合回归；固定官方 Client 及增强的六项受控复用测试；原生诊断的人工触发、清理和迟到登记回归，以及分级报告的命令行行为测试。优先扩展这些边界，不新增一套平行控制器或为纯包装代码堆叠测试。

原生 self-test 只能证明真实 ToolRuntime 流水线，不能代替最终模型自主选择并调用工具的验收；固定计数按钮也不能代表任意网页操作已通过。

### 首版验收矩阵

编号沿用完整设计，方便核对范围。以下均为完成条件，历史部分证据不能将整项标为通过。

| 编号 | 场景与通过条件 | 主要验证方式 |
| --- | --- | --- |
| A01 | 原入口、快捷键、官方外观、原生页面、导航可用；卸载恢复 builtin，无注册或样式冲突。 | 固定版本组合回归与真实 Desktop 启停。 |
| A02 | 人工修改后工具读到新状态，Agent 操作立即出现在同一页；页面和文档身份一致。 | 真实工具调用及可见结果；含模型自主调用。 |
| A03 | 中文输入法、复制粘贴、滚动正常；Agent 指针不移动系统鼠标，普通浏览无强制交接。 | 真实 Desktop 人工与工具组合场景。 |
| A04 | 导航、重排、滚动、frame 或文档变化后旧引用失效或重新定位；无法确定目标时拒绝。 | 控制边界竞态回归及动态测试站。 |
| A05 | 接管覆盖全部 Agent 读写、订阅、缓存和后台任务；不交付迟到结果，不留存接管期采集，交回先观察。 | 延迟与持续任务回归，加真实暂停/交回。 |
| A06 | 两会话双向越权拒绝；伪造、过期、关闭和其他窗口目标不能误绑定。 | Broker/正式通路回归与两个真实会话。 |
| A07 | 默认全局与可选工作区共享均成立；切换不复制、不删除、不改变旧页面，且不扩大页面权限。 | 两工作区、多个会话、多个容器的真实验证。 |
| A08 | 隐藏和切会话保活且不抢焦点；关页、卸载撤销控制，迟到登记与回调不能复活页面。 | 生命周期回归与真实 Desktop；含在途关闭。 |
| A09 | 重启恢复网址、会话和容器关联，按需重新登录；不恢复表单或重放动作。 | 实际重启验收，独立于受控 checkpoint 测试。 |
| A10 | 普通表单填写可用；敏感提交先审批，拒绝、目标变化或审批不可用时不执行。 | 可控测试站和正式审批通路。 |
| A11 | 跨站导航与所需跨域 frame 正确感知操作、归属正确；不把无能力当空白成功。 | 跨源测试站与真实 guest，缺口保持阻塞。 |
| A12 | 指定文件及网站经确认后上传成功；取消、无权限、文件或页面变化明确失败或要求重新授权。 | 临时自有文件、上传测试站与公开宿主文件能力。 |
| A13 | Agent 与人工下载路径按当前宿主限制明确不支持，无伪造成功文件或替代请求。 | 自有下载测试站及真实 Desktop。 |
| A14 | 基础控制台和获批脚本只作用于当前会话页面；同样受接管、取消与逐次审批控制。 | 订阅清理和审批回归，加真实脚本/控制台验收。 |
| A15 | 断线、超时、取消和重复请求结果明确；不换页执行、不自动重试结果不明的敏感动作。 | 注入延迟/断连的边界回归及真实恢复场景。 |
| A16 | 缺失能力与版本不匹配明确说明，不走私有接口或虚报兼容。 | 能力组合回归和实际版本记录。 |
| A17 | 获准真实网站浏览与人工登录后的任务可核验；验证码或风控交人，失败不报完成。 | 用户授权的非破坏性人工/Agent 联合验收。 |

### 校验、证据与首版完成定义

- TypeScript、构建、ESLint 和 vitest 遵循仓库统一门禁，测试仅放插件包根级测试目录，不进入发布产物；不引入 Prettier。
- 官方固定发布产物的受控测试须显式准备对应产物；普通测试的跳过不能算通过。最终报告写清实际执行数和跳过数。
- 构建、协议组合、当前 Host 运行、真实原生验收分开记录。历史 JSON 只代表记录；分级 CLI 不因读取历史证据而生成本次原生通过结论。
- 每项真实验收保留宿主/插件版本、构建摘要、步骤、观察、页面与文档关联、未测项及必要的可见证据；不保存 Cookie、控制凭据、密码或无关会话内容。
- G1–G5 和 A01–A17 的首版条件均满足，全部首版保留用户故事有对应证据后，才能声明首版完成。部分工程增量可以独立完成，但不能冒充整体交付。
- 下载、完整调试和跨重启登录态仍作为明确后续目标，不计入首版成功能力，也不能据此取消上传、全局登录态或其他首版保留项。

## 不在范围内

- 重写官方浏览器界面、另建浏览器壳、自建 CDP 兼容层，或迁移 builtin 已打开页面。
- 修改 DSH 主程序、安装包、私有 controller 或私有 IPC；用其他 Desktop 客户端、Web、CLI、外部浏览器、iframe 降级或画面流替代本规格。
- 未经实际验证的其他操作系统兼容声明，以及自动导入普通浏览器、DSH 主界面或其他应用的 Cookie、密码和历史。
- 首版网页文件下载；完整 Network、断点、原始 CDP；跨应用重启的登录态持久化。它们是延期项，不是永久删除。
- 自动恢复未提交表单、重放旧操作、绕过验证码或网站风控、保证任意网站可自动化，以及承诺暂停能撤回已发送内容或逆转已发生操作。
- 无审批的任意脚本、跨会话页面操作、把账号容器共享当成页面授权，以及无限制宿主文件或 Node 访问。
- 本轮产品实现、发布、自动提交或创建远端事项。后续拆分与实现不由本地规格文件的产生自动启动。
